# CS-305
## Artemis Financial Security Assessment

Artemis Financial is a financial technology company that needed stronger software security for its applications and customer facing systems. The issue was that the company’s software had security vulnerabilities that could expose sensitive financial data and create risk for customers, the business, and its reputation. My task was to assess the application, identify weaknesses, and implement secure coding practices and mitigation strategies to reduce those risks.

I did well by systematically reviewing the application for security flaws, prioritizing the most serious issues, and applying practical fixes that improved the code’s resilience. It is important to code securely because even small mistakes can lead to data breaches, loss of trust, and financial harm. Secure software protects sensitive information, reduces downtime, and helps a company remain compliant with industry expectations. Software security adds long-term value by protecting assets, supporting customer confidence, and making the business more reliable and sustainable.

The most challenging and useful part of the vulnerability assessment was reviewing the code for weaknesses and understanding how the software could be exploited in real-world scenarios. This helped me connect theory to practice and think like both a developer and a security reviewer. It was especially valuable to identify how coding choices, library usage, and configuration decisions could create vulnerability exposure.

I increased layers of security by implementing secure coding practices, validating data, reducing unnecessary exposure, and strengthening the application against common threats. In the future, I would use vulnerability assessment tools such as static analysis, dependency scanners, and security testing frameworks to identify weaknesses and then decide on mitigation techniques based on risk, impact, and the specific software context.

To make sure the code and application were functional and secure, I tested the software after refactoring and verified that the changes preserved required behavior while strengthening protections. After refactoring, I checked for new vulnerabilities by reviewing the updated code, testing functionality, and using security analysis tools to confirm that the fixes did not introduce weaknesses or break the application.

The resources and tools that were helpful included secure coding best practices, code review techniques, vulnerability analysis tools, and testing practices. These habits are useful in future assignments and professional work because they help prevent problems before they reach production and support better-quality software development.

From this assignment, I could show future employers examples of my ability to assess software for security risks, improve application resilience, and apply practical remediation strategies. This demonstrates that I can think critically about software quality, protect business assets, and contribute to secure and reliable development practices.
